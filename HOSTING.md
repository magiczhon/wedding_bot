# Где разместить сервис: сравнение хостинг-провайдеров

*Состояние на конец сентября 2026 года. Цены и условия меняются часто: в конце 2025 — начале 2026 года провайдеры подняли тарифы на 8–20%. Перед покупкой сверяйтесь с сайтом провайдера.*

## Коротко

- **Сервер — только в России.** Бот хранит имена и ответы гостей, а персональные данные граждан РФ по 152-ФЗ должны храниться в российской базе. Кроме того, с 1 февраля 2024 года услуги хостинга в России могут оказывать только провайдеры из реестра Роскомнадзора. Все крупные российские провайдеры в нём есть.
- **Главный технический риск — Telegram.** С марта 2026 года из части российских дата-центров не проходят запросы к `api.telegram.org`: на Хабре и vc.ru называют Selectel, Reg.ru и Jino. ВКонтакте работает без ограничений. Решение — маленький **ретранслятор за рубежом**, через который идут только запросы к Telegram, а база остаётся в России. Бот уже умеет так работать: в `config.json` достаточно указать `telegram.api_url` (подробнее — [ниже](#ретранслятор-для-telegram)).
- **Ресурсов нужно мало.** Хватит 1–2 vCPU, 1–2 ГБ памяти и 10–20 ГБ диска: это десятки свадеб одновременно. Сервис — один процесс на Python (бот + веб-панель) и SQLite.

**Рекомендации**

| Ситуация | Что взять | Примерно в месяц |
|---|---|---|
| Запуск, первые клиенты, готовы администрировать сервер | **Timeweb Cloud** Cloud-40 (Москва/СПб) + маленький сервер Timeweb в Нидерландах или Казахстане под ретранслятор | от 900 ₽ + ретранслятор |
| То же, но дешевле и с бесплатными бэкапами | **Beget** VPS 2 vCPU / 2 ГБ (СПб) + VPS Beget в Казахстане под ретранслятор | ~810 ₽ + ретранслятор |
| Не хочется администрировать сервер вообще | **Amvera** — деплой из Git, прокси до Telegram встроен | 290–490 ₽ |
| Бюджет ноль, эксперименты | **Cloud.ru Evolution Free Tier** — бесплатная ВМ + платный публичный IP | ~150 ₽ |
| Клиенты-агентства требуют документы о защите ПДн | Аттестованный сегмент 152-ФЗ: Timeweb Cloud, Selectel, Cloud.ru, VK Cloud, Yandex Cloud | по запросу, у Selectel — от ~30 000 ₽ |

Мой выбор для старта — **Timeweb Cloud**. У него серверы в России и за рубежом в одном аккаунте с оплатой в рублях: основной сервер и ретранслятор покупаются у одного провайдера. Есть почасовая оплата, а когда клиентам понадобятся документы, можно перейти в сегмент 152-ФЗ там же. Если не хочется настраивать Linux, nginx/Caddy и бэкапы, берите **Amvera**. Но уточните у них вопрос о 152-ФЗ: на странице тарифа он не упоминается.

## Что нужно сервису

| Требование | Почему |
|---|---|
| Сервер в России у провайдера из реестра РКН | Локализация персональных данных (152-ФЗ, ст. 18 ч. 5) и закон о хостинге |
| Доступ к `api.telegram.org` — напрямую или через ретранслятор | Иначе бот в Telegram молчит; ВКонтакте работает из России без проблем |
| 1–2 vCPU, 1–2 ГБ RAM, 10–20 ГБ диска | Бот и панель — один процесс; SQLite хватит на сотни мероприятий |
| Постоянно работающий процесс | Бот получает сообщения через long polling, входящие порты для этого не нужны |
| HTTPS для веб-панели | Логины организаторов и персональные данные гостей не должны идти открытым текстом |
| Резервные копии базы, хранящиеся в России | В базе — персональные данные; бэкап подчиняется тем же правилам |

Serverless-платформы (функции с оплатой за вызов, например Yandex Cloud Functions) сейчас не подходят: бот работает через long polling и держит состояние в памяти. Нужен обычный сервер или контейнер, который работает постоянно.

### Зарубежные провайдеры (Hetzner, DigitalOcean и т. п.)

Как основной сервер **не подходят**: база с персональными данными граждан РФ должна находиться в России, а оплатить такие сервисы российской картой сложно. Их можно использовать только как ретранслятор — через него не хранятся никакие данные.

## Ретранслятор для Telegram

Схема: бот и база работают на российском сервере, а запросы к Telegram идут через маленький сервер за рубежом. На ретрансляторе ничего не хранится, он только передаёт запросы.

1. Возьмите самый маленький сервер за рубежом: у Timeweb Cloud — Нидерланды, Германия или Казахстан, у Beget — Казахстан. Направьте на него поддомен, например `tg-relay.example.ru`.
2. Установите [Caddy](https://caddyserver.com) — он сам получит HTTPS-сертификат. Разрешите доступ только с IP российского сервера, иначе ретранслятором сможет пользоваться кто угодно:

   ```
   tg-relay.example.ru {
       @bot remote_ip 203.0.113.10          # IP вашего российского сервера
       handle @bot {
           reverse_proxy https://api.telegram.org {
               header_up Host api.telegram.org
           }
       }
       respond 403
   }
   ```
3. В `config.json` на основном сервере:

   ```json
   "telegram": {
       "token": "TELEGRAM_BOT_TOKEN",
       "api_url": "https://tg-relay.example.ru"
   }
   ```
   Вместо ретранслятора можно указать прокси: `"proxy": "socks5h://user:pass@host:1080"`. Для SOCKS нужен пакет `pip install "requests[socks]"`.
4. Перезапустите бота и проверьте журнал: должна появиться строка «Telegram API через https://tg-relay.example.ru».

Через ретранслятор проходят токен бота и текст сообщений, поэтому держите его под своим контролем и не пользуйтесь публичными «бесплатными» прокси. С юридической стороны: в сентябре 2025 года Роскомнадзор разъяснил, что обмен персональными данными через иностранный мессенджер между сторонами, находящимися в России, **не считается трансграничной передачей**. Хранить базу при этом всё равно нужно в России. Детали уточните у юриста.

## Как развернуть на VPS (Ubuntu 24.04)

```bash
# 0. Пакеты (Caddy — по инструкции с caddyserver.com/docs/install)
sudo apt update && sudo apt install -y git python3-venv sqlite3 ufw

# 1. Пользователь и код
sudo adduser --system --group --home /opt/wedding_bot wedding
sudo -u wedding git clone https://github.com/magiczhon/wedding_bot /opt/wedding_bot
cd /opt/wedding_bot
sudo -u wedding python3 -m venv .venv
sudo -u wedding .venv/bin/pip install -r requirements.txt
sudo -u wedding cp config.example.json config.json    # заполните токены, secret_key, privacy
sudo -u wedding .venv/bin/python manage.py create-admin owner
sudo -u wedding mkdir -p /opt/wedding_bot/backups
```

Автозапуск — `/etc/systemd/system/wedding-bot.service`:

```ini
[Unit]
Description=Wedding bot and admin panel
After=network-online.target
Wants=network-online.target

[Service]
User=wedding
WorkingDirectory=/opt/wedding_bot
ExecStart=/opt/wedding_bot/.venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now wedding-bot
journalctl -u wedding-bot -f         # журнал
```

HTTPS для веб-панели — Caddy (`/etc/caddy/Caddyfile`); панель при этом слушает только `127.0.0.1:8080`:

```
panel.example.ru {
    reverse_proxy 127.0.0.1:8080
}
```

В `config.json`: `"web": {"public_url": "https://panel.example.ru", "https": true, ...}`.

Файрвол — открыть только SSH и HTTPS:

```bash
sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw enable
```

Ежедневный бэкап базы (`crontab -e` от пользователя `wedding`). Копии храните в России: на том же сервере и в объектном хранилище российского провайдера.

```
15 3 * * * sqlite3 /opt/wedding_bot/guests.db ".backup '/opt/wedding_bot/backups/guests-$(date +\%F).db'" && find /opt/wedding_bot/backups -name 'guests-*.db' -mtime +14 -delete
```

## Юридический чек-лист перед запуском

- [ ] Сервер и бэкапы — в России, у провайдера из [реестра хостинг-провайдеров РКН](https://rkn.gov.ru/press/news/news74803.htm).
- [ ] Подано уведомление в Роскомнадзор об обработке персональных данных. Бот обрабатывает их автоматически, поэтому уведомление нужно и самозанятому, и ИП.
- [ ] В `config.json` указаны оператор, контакты и срок хранения. Страница `/privacy` проверена юристом.
- [ ] Если позже будете рассылать гостям рекламу (партнёров, подрядчиков), понадобится отдельное согласие по закону о рекламе (38-ФЗ). Сообщения о самом мероприятии — это не реклама.
- [ ] Когда клиентами станут агентства, им может понадобиться договор поручения обработки ПДн и размещение в аттестованном сегменте 152-ФЗ.
